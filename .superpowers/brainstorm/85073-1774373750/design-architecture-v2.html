Design Section 1: Component Architecture (revised)

How the pieces fit together

Usage Patterns

Convenience wrappers (simple usage)
// Month view
<MonthView
value={...}
min={...} max={...}
locale="en-US"
numberOfMonths={2}
overflowBehavior="contain"
>
<Grid>...</Grid>
</MonthView>
// Weeks view
<WeeksView
value={...}
min={...} max={...}
locale="en-US"
weekCount={8}
firstWeek={...}
overflowBehavior="clamp"
>
<Grid>...</Grid>
</WeeksView>
Composed usage (both views sharing state)
<CalendarProvider
value={...} min={...} max={...} locale="en-US"
>
<MonthView.Root numberOfMonths={1}>
<Grid>...</Grid>
</MonthView.Root>
<WeeksView.Root weekCount={6} firstWeek={...}>
<Grid>...</Grid>
</WeeksView.Root>
</CalendarProvider>

Migration

Current Root is replaced by MonthView. This is a breaking rename — no backwards-compat shim. The convenience wrappers (MonthView, WeeksView) merge CalendarProvider props + view-specific props into a single component for simple use cases.
